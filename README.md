# 情緒不孤島 v4.0

八組各自加分、佈置小世界；島嶼隨分數升起，土地擴張，小精靈與 NPC 陸續入住。主領班「星願神境」為完整佈置的獨立展示，不列入排行。

## 正式入口與升級

- 連結產生器：`emotion_links.html?room=2026`。原有 `202601`～`202608` 連結繼續使用。
- 舊分數、成長分數、剩餘點數、組名與小精靈姓名保留在 `rooms/{room}/emotionV3/groups/{group}`。
- 升級時換成不同主題的新版地圖與預設建築。原倉庫物品保留，舊地圖上已擺放的物品全部收回倉庫；不會清除已購買物品。新版佈置、庫存、任務、聊天和獎勵分數放在旁邊的 `worldsV4/{group}`。
- 每組只升級一次。之後重新整理或再次發布，不會清除新佈置。舊版加分頁也不會覆蓋新版佈置資料。
- 已有小島的倉庫數量＝原庫存＋原島上擺放數量，可用點數保持原值，不重新發放開場點數。只有全新建立的小島才有預設長椅 1、花叢 2、庭園燈 1。
- `node tools/migrate-v4.mjs ROOM` 為預檢，加 `--apply` 才執行升級。每次交易先備份原資料到倉庫外，再逐一檢查保留欄位。

## 分數與獎勵

- **活動加分**：各組自行填寫的分數，欄位仍為 `groups/{group}/score`。
- **獎勵分數**：NPC 和任務的分數，獨立放在 `worldsV4/{group}/rewardScore`，升級時為 0。
- **排名總分**＝活動加分＋獎勵分數。獎勵同時增加成長進度與可用點數。
- 每位 NPC 每天首次聊天，全組獲得 **5 獎勵分數**，臺灣時間午夜換日。隨時都能再聊天，無須等加 100 分；重複聊天不會再次加分。
- 每個任務首次完成，贈送指定家具／設施與 **50 獎勵分數**。建設任務必須實際擺放並儲存；領獎視窗列出物品與分數。
- 每 100 分增加一位可命名、換裝的小精靈，依本組人數設定 1～30 位，預設 10。
- 原有 45 件商店品項保留，含生活小物共 50 件，單價均為 100 點。

## 土地與居民

| 成長分數 | NPC 人數 | 新開放區域 | 全島主動招呼間隔 |
|---|---|---|---|
| 0 | 1 | 主島與溪光草坪 | 45～60 秒 |
| 400 | 2 | 東岸新草坪 | 35～48 秒 |
| 800 | 3 | 西邊花園地 | 28～38 秒 |
| 1200 | 4 | 後山觀星地 | 22～32 秒 |
| 1600 | 5 | 南岸慶典地 | 16～24 秒 |

招呼只計算前景觀察時間；佈置、面板與背景期間暫停，不會強制彈出對話。居民情境對話依角色、日夜、成長與任務進度輪替，碰面互動也隨等級增加。

主畫面中央不孤島有多層宮殿、花園、階梯、水庭與瀑布。八組島嶼依排名總分逐漸浮起，**1600 分才顯示與中央島的連線**，之後分數仍可增加。

## 編輯與唯讀

從某組編輯連結進入，只有該組可以加分、佈置；其他島一律唯讀，回自己的島可繼續編輯。直接開啟唯讀連結，整趟旅程都維持唯讀。這沿用原專案以連結區分操作模式的方式，並未新增登入驗證。

參觀介面沒有連結產生器入口。「前往不孤島」開啟唯讀主畫面。若有未儲存的佈置，離島前可選「儲存後前往」「留在小島」或「捨棄此次修改並前往」。

## 同步與部署

Firebase REST 條件交易（ETag）處理同時加分、購買、佈置與領獎；操作收據防止回應中斷造成重複發獎。主畫面約每 2.5 秒、編輯頁每 4 秒、唯讀頁每 12 秒更新，回到分頁立即更新，背景分頁暫停。

```sh
npm test
npm run build
npm start
```

本機預設 `http://127.0.0.1:2027/emotion_links.html?room=2027`，只使用獨立瀏覽器存檔。加上 `cloud=1` 才測試 2027 雲端資料，本機不接受 2026 雲端測試。

專案是純靜態 HTML、CSS、ES modules，Three.js 與素材放在倉庫內。支援既有 Vercel GitHub 整合，也支援 GitHub Pages 的專案子路徑。Vercel 設定見 `vercel.json`；Pages 分支部署使用 `main` 根目錄。

舊版說明保留於 [docs/README_v351_history.md](docs/README_v351_history.md)。活動資料備份留在倉庫外，不會提交到公開 GitHub。
